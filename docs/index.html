Why this exists

Three principles. Nothing else.

A new Mac is a clean Mac. The repo gets cloned, one command runs, every tool is back — and every change is reversible without archaeology.

01

One-command install

./install.sh sets up the kbro CLI, ZSH integration, TMUX config, and Claude skills + preferences. --dry-run previews every change first.

02

Idempotent re-runs

Running the installer twice is a no-op. Marker blocks are compared by body content; symlinks are checked before refresh. Backups are stamped and de-duplicated.

03

Safe uninstall

Every touchpoint in $HOME lives inside a BRO-TOOLKIT-MANAGED block or a namespaced symlink. ./uninstall.sh reverses all of them — nothing copied, nothing inlined.

Architecture

Dotfiles point at the repo. The repo holds the logic.

Each user file gets exactly one line inside a marker block. Real configuration stays inside the repo — so git pull updates everything with no re-install.

CLI surface

The kbro dispatcher

One binary, eight verbs. New tools land here so you never have to remember a second name.

kbro helpShow usage and current paths.
kbro versionPrint version from the VERSION file.
kbro statusSummarize each component's install state from ~/.bro-toolkit-state.json.
kbro doctorDetect drift: missing symlinks, stale marker blocks, non-executable scripts.
kbro install [comp]Install all or one component. Accepts --dry-run.
kbro uninstall [comp]Reverse all or one component. Accepts --dry-run.
kbro updategit pull --rebase --autostash in the repo, then re-run the installer.
kbro listList bundled Claude skills (with descriptions) and PATH-exposed tools.
Idempotency

Four lines that make this safe

Re-running the installer hashes the marker-block body against what's expected. If it already matches, nothing changes. If it doesn't, the old block is removed and the new one appended.

# ~/.zshrc — the entire footprint we leave behind

# >>> BRO-TOOLKIT-MANAGED >>>
[ -f "$HOME/claude/bro-toolkit/rc/zsh/bro.zsh" ] \
  && source "$HOME/claude/bro-toolkit/rc/zsh/bro.zsh"
# <<< BRO-TOOLKIT-MANAGED <<<

Reversal recipe

  1. Backup the file once per uninstall run to ~/.bro-toolkit-backups/<ts>/.
  2. Strip every line from BEGIN through END using an awk filter.
  3. Trim trailing blank lines so the file doesn't grow.
  4. Record the change in ~/.bro-toolkit-state.json so kbro status reflects it.

Backups are kept after uninstall — you can audit or restore them by hand.

Layout

Repository structure

Each top-level directory has exactly one job. New components add files; they don't reorganize.
